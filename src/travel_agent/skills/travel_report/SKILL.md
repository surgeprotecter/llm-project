---
name: travel_report
description: 完整旅行攻略的研究、交通、排程、住宿和HTML产物，或对已有报告进行针对性修改；普通咨询和组合比较不适用。
---

完整报告优先用itinerary_step各项能力提交结构化成果；原生查询用于定向补查和专项问题，已有实查结果可直接复用。先prepare与route取得工作区和城市日期骨架，避免研究和报价没有归属。
用户要求生成HTML旅行报告时，使用标准模板和完整内容校验。旧聊天行程可以帮助恢复目标、城市与已确认选择。只有明确要求原样导出已有内容才用复制导出。
复杂报告先update_plan创建动态任务清单；每完成可交付部分就更新状态和真实结果引用。
itinerary_step是可组合能力，由你选择下一步；通常一次只推进一个城市/交通段/住宿段，返回pending_targets或pending_segments时继续相应操作。错误或部分成功不代表整体完成。
1. 先用update_trip只记录用户明确给出的地点、日期、人数、全体预算与偏好。已有事实不重复询问；
   人均预算乘人数，“至少/上不封顶”用budget_min与null上限。航班升级仅更新flight_preferences。
2. prepare：request说明本轮真实任务。首次报告sections可以不填；局部修改仅选直接相关部分：
   route、days、hotel_regions、transport、food、budget、notes、insights。
   targets限定城市；transport_target为external往返、intercity城际或all，单段用target_transport_ids。
3. 没有城市骨架或需改变城市时route；只换酒店、航班时沿用既有路线。
4. research：按城市targets补充有正文来源的体验，餐饮融入每日行程。城市已有充足资料可以保留。
   某项明确体验未被旧资料覆盖时用purpose=coverage_repair，按当前城市与用户偏好扩展新检索；不要仅重读原来相同几篇笔记。
5. transport：只查受影响交通；首次报告通常需要。external表示出发地往返目的地，
   即使乘高铁也属external；intercity是旅途中多个停留城市之间。返回实际抵离时刻后再schedule。
6. schedule：用有来源点位与交通安排每日内容；完整游览日通常2—3个合适主要体验，
   全天活动、转移、抵离和休息日可以例外；时间冲突或某城内容过少时先定向补查/调整。
   需要调整同日跨城或赶航班的道路接送时，用transfer_changes=[{id:准确交通段ID,date:出发日期,departure_time:HH:MM}]；
   改过夜城市用stay_changes=[{day:第几天,city:已知城市}]，随后hotels更新受影响住宿。仅写在request中不会改动时刻。
   时刻调整只能用于已有道路估算，不能编造公共交通班次。根据实查耗时倒推接送出发，国际航班需至少提前3小时抵达机场；
   不增加城市日历槽也能在一天中顺路游览另一城市、改住那里。保持原已选航班可避免无必要重查。
7. hotels：依实际住宿夜晚查询，局部修改targets指定城市；预算基准酒店只计一次。
   如已研究并决定采用某家酒店，传hotel_choices=[{city:城市名,url:真实检索到的完整酒店URL}]；
   系统会核对来源并取得相应日期真实报价，再将其设为预算基准。不要只在文字里说换好了。
8. export_report operation=render：汇总预算、校验并渲染标准HTML与Markdown。实际quality及issues返回后判断是否需要定向修复；
   未解决的缺口必须称草案。最终回复给出真实产物路径、概要、估算单位和必要局限。

工作区进度在上下文中，可直接查看已完成步骤和记录数量。不反复读取整个报告。
独立或依赖已明确的操作可以批量顺序提交，收到结果后再判断是否修复；不要每个操作都加载同一技能。
原生工具取得的结果保存在持久结果索引。先read_result确认内容，将真实result_id通过itinerary_step.result_refs关联到报告，避免同样条件再次查询。
用户选定候选后，用select_result保存准确结果ID、候选序号及用途，同时记录明确决定；后续沿用这个选择。
航班用于预算时需明确计价人数。需要明确单人参考价可查询passengers=1，给出全体估算与库存限制；不要重复查询相同条件。已有资料能核实单位时直接复用。
研究或交通资料不足时应定向补查；读取笔记正文，不凭搜索标题编造体验。

不能在用户只想探索或解释时调用这套操作。已有报告不等于本轮要更新报告。
修改保持未受影响的景点、交通、住宿和证据；若新航班改变可用时间，必要时重排对应日并解释，
不可悄悄使用不兼容的旧酒店日期。不要因为一次操作失败就把底层错误发给用户。
“安静”应结合位置和实际客评核实，不能仅凭位于市中心就断言嘈杂；缺少客评时明确待核验。
