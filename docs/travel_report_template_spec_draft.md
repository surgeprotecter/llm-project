# 旅行报告 HTML 版式规范（第二版草案）

状态：第二版视觉样式已确认并接入。正式模板为 `src/travel_agent/reports/templates/travel_report_standard.html`。当前 [`travel_report_standard_draft.html`](../src/travel_agent/reports/templates/travel_report_standard_draft.html) 是**已填充内容、可直接打开的静态样稿**，不含 Jinja 占位符，仅作为版式参考保留。所有示例价格、日程时间和交通耗时均在页面显著标注为演示值。

## 内容层级

1. **首屏**：目的地、天数、日期、人数、预算目标、四天路线速览。
2. **行程概览**：点位数量、住宿安排、规划取舍。
3. **逐日安排**：每天 2–3 个主要点位，按时间顺序展示停留理由、相邻点位交通和当日节奏；抵达日、返程日可减量并说明原因。
4. **交通与住宿**：市内通勤、往返航班、每片区 1–2 家酒店；展示价格、计价周期、优劣势、跳转链接，并指定一间预算基准酒店。
5. **预算**：机票、酒店、市内交通、跨城交通（长线时）、门票、餐饮、机动费用分项；标清人数、币种、查询时间和来源。关键价格缺失时只显示已有分项与缺口，不显示完成态总额。
6. **笔记整理**：先读正文，再按景点或观点合并重复信息，保留冲突意见和来源。
7. **出发前确认**：列出会改变路线和费用的航班、酒店、地图与景点规则。

## 路线规则

- 3–4 天短途：默认集中在单城或相邻片区，尽量连住；以步行和短途打车串联，不添加无意义的跨城段。
- 7/14 天长途：先按城市或远距离片区拆段；展示跨城高铁/航班段、换城日期和每段住宿；不要每天往返跨城。
- 同一天的点位须能由笔记正文或其他可靠内容支撑，再用地图核验位置、距离、耗时和顺序。相距过远的点移动到备选。
- 酒店必须在确定主要点位片区之后筛选。优劣势来自价格、位置、设施或评论；缺少资料时不编造。

## 视觉约定

- 整页使用白底、统一边框卡片和少量浅绿色强调区；深绿色只用于路线速览与预算结论，避免交替大面积灰白底。
- 一屏内优先展示结论和路线，不让技术状态、模板字段或来源日志占据主要视觉位置。
- 手机下改为单列，目录可横向滚动；打印时尽量避免拆断每日卡片。
- 外链新标签打开并带 `noopener noreferrer`。

## 调研依据

- [Earth Trekkers 的 12 天行程](https://www.earthtrekkers.com/new-england-road-trip-itinerary/)把总览、路线、每日安排、住宿、车程与实用提醒放在同一篇攻略里。
- [Rick Steves 的行程规划建议](https://www.ricksteves.com/travel-tips/trip-planning/itinerary-tips)强调核对交通时间、控制换酒店频率，并让行程适配时间与预算。
- [Google Travel 的酒店搜索说明](https://support.google.com/travel/answer/6276008)列出位置、价格、评分、评论、设施和预订链接等酒店比较信息。
- [Lonely Planet 的 7 天巴厘岛攻略](https://www.lonelyplanet.com/articles/bali-itinerary)按天说明活动、交通、住宿片区和出行提醒。

这些资料用于确定报告应该包含哪些信息与如何排序；样稿中的成都具体数值是布局示例，不从上述资料推导。
