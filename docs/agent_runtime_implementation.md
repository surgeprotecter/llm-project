# Agent 运行机制实现说明

实施与真实验收：2026-11-17 至 2026-11-18。对应已批准的 `agent_runtime_optimization_plan.md`。

## 主循环

真实模式使用 `RuntimeEngine` 和 `DurableAgentGraph`：恢复任务 → 构建上下文 → 模型选择回答或工具 → 执行并保存 → 再交给模型。报告操作是模型可以选择的能力，普通交流不强制生成报告。

每次收到输入，先根据公开对话判定请求场景与用户要求，并保存 `request_scope`。计划提议与执行进度分别保存。用户同意当前版本后，才开启执行工具；执行中通过 `update_plan` 更新清单并关联真实结果。进度询问可直接交付，同时保留正在执行或等待确认的计划。

真实模式继续使用可续跑的 LangGraph 检查点。候选答复只用当前场景的规则检查。检查返回单一动作：通过、改写、补查、追问或受阻。改写可直接使用检查器给出的修正版；补查需要对应用户要求。纠正意见由系统消息传回，用户授权只来自实际用户消息。

对重复且未改变业务状态的读取，提示无新结果；必要时暂时收起读取工具，允许回答已有状态或选择其他实际操作。这个机制不按累计用量结束任务。

## 状态与持久化

| 数据 | 保存位置 | 内容 |
| --- | --- | --- |
| 当前任务 | SQLite `runtime_sessions` | 根目标、动态计划、运行状态、用户事实、当前工作区、摘要、加载的能力、选定候选、近期消息 |
| 历史任务 | `runtime_task_history` | 完成后归档的任务与成果状态 |
| 工具完整结果 | `runtime_results`、原有 `tool_executions` / `evidence_items` | 参数、来源、实际结果、时间、引用 ID；结果与当前任务关联 |
| 运行检查点 | LangGraph `checkpoints` / `writes` | 原生调用协议、图执行位置和节点状态 |
| 已写出报告 | `reports` 和输出目录 | 各版 HTML、Markdown、结构化快照 |

工具返回即落盘。研究过程中每篇正文、提取结果及核验点位可以增量保存；城市、交通段、住宿段和逐日日程分别提交。中断调用不会被假定成功，恢复时补齐协议消息，优先使用已保存结果继续。

工作区是正在编辑的成果，已渲染报告是文件快照，两者在编辑过程中可能不同。上下文明确区分二者，包含当前点位选择、每日安排、交通生效时刻、住宿价格及其引用索引。修改后工作区标记为未渲染，写出成功后才标记为已渲染。

程序选择的候选与用户明确确认的事实分开保存。已修复旧版 `select_result` 把自由文本用途写成用户事实的问题，兼容清理有执行记录证明的旧自动写入，保留显式 `update_trip` 确认。

## 上下文与结果读取

稳定规则、能力目录和技能放在前部；当前精确状态、材料索引和近期消息按需要进入模型。MCP Schema 按 `inspect_tools` 加载；技能正文按 `load_skill` 读取，不把全部工具正文无限累加。

完整结果保存在数据库，预览与完整存储分开。`read_result` 支持字段路径、列表下标和实际分页；`next_offset` 根据实际返回条数计算。`read_state days` 的数字目标按天数精确匹配。日程索引保留全部时间块，避免嵌套餐馆、图片、长 URL 挤掉后半段。旧版已经截断的内部记录会明确提示改读当前工作区。

工作窗口默认 36000，用来安排上下文整理，不是任务 token 预算。Flash 增量总结旧调用组，保留近期组；近期组本身过大时也纳入摘要。摘要同时读取当前工作区和用户精确状态，不能只依据旧的模型叙述。原始调用始终可回查。

DeepSeek 输出上限通过原样透传的 `extra_body.max_tokens` 设置，避免 ChatOpenAI 将其改名成服务商未采用的字段。真实 16-token 请求验证过实际输出上限。结构化结果若确因长度截断，进行一次有记录的紧凑 JSON 重试；余额或认证错误不改用另一模型反复重试。

## 工具执行与复用

对工具名称与规范化参数建立指纹，在仍适用时复用成功结果，并保留原查询时间。修改日期、人数、币种等会改变匹配；`refresh_tool` 可按明确原因主动刷新。

同一有状态 MCP 服务串行，不同服务可以有限并发，各工作线程使用独立 SQLite 连接。MCP 会话持续复用。模型和 MCP 请求支持取消，SIGINT 后保存已完成数据；真实运行观察到约 0.2–1.4 秒退出，不据此承诺所有网络场景的退出时限。

直接查询的航班、Booking 候选、小红书正文及网页摘录可以关联到报告。网页摘录标明来源类型，不冒充完整小红书笔记。多人航班保留原始人数、全体报价、折算人均及原结果 ID，用户或模型选定的候选可直接采用。

## 报告操作与局部修改

保留 `prepare / route / research / transport / schedule / hotels / render` 这些可组合业务能力，不把它们设为所有请求的固定主循环。

依赖检查会阻止在尚无交通依据时排程、按过期日程查酒店、用旧日程直接渲染。模型获得具体缺口后决定如何处理。道路接送的计划时刻可通过 `transfer_changes` 调整，住宿地可用 `stay_changes` 调整；不会改写真实航班或公共交通班次。

未指定的入境道路接送根据真实落地时间预留办理手续和接驳窗口，不能默认在落地前出发。同日跨城可在真实转移窗口前安排已有来源的体验。用餐检查完整时间区间，不能只检查开始时刻是否重叠。

`selected_place_ids` 调整相应城市内的选择，保留其它城市；排程缓存包括路线、点位、选择集合、交通和过夜地，避免更换选点后继续使用旧日程。旧版局部覆盖损坏的草稿可以从最近通过校验的报告恢复未受影响的选点。

路线分配期间的模型意见单独归档为 planning_notes，不拼接到当前摘要。最终路线说明从实际住宿顺序、所选航班抵离时间与交通估算状态生成；评论变化不会触发日程重新计算。旧版原始意见保留可回查。

HTML 与 Markdown 沿用标准模板。主模型负责定性解释；新文件的最终交付回执直接读取报告的金额、人数、晚数、版本和文件路径，防止把两人合计再乘人数、把住宿段数当晚数。

## 验收与局限

真实验收记录、所有失败轮次、模型输入输出及用量保存在 `output/runtime-upgrade/`。未运行旧的 Mock 测试套件，使用真实模型、MCP、API及真实缓存结果；另外做过静态检查、已有真实数据的完整性校验和浏览器布局检查。

两个场景分别覆盖国内短程多轮修改，以及国际长程多城市、中断恢复、再作局部调整。验收经历过失败和修复，不能称为两个冷启动一次通过。主用户数据库在修改前备份，付费测试使用隔离数据库。

本轮调试消耗显著过高，包含错误预览、重复读取、旧摘要和失败重试。用量应以验收 JSON 的服务商统计为准；本轮结果不能用于声称某个节省比例，也没有做最终版本的长程冷启动成本对照。境外交通未取得可核实票价的部分仍明确使用估算或预留，报告不是已锁库存或已预订结果。

## 本地使用

```bash
uv run travel-agent chat --real-only --trace --user-id yuming --trip-id runtime-selftest
```

相同 user-id / trip-id 恢复同一任务和材料。已批准的未完成任务可输入“继续”，待确认的计划仍需确认后执行。新旅行使用新的 trip-id。`--trace-full` 查看模型输入输出，`--trace` 查看用量、场景、检查决定和工具概况。

复核已保存验收数据，不产生新 API 费用：

```bash
uv run python scripts/audit_runtime_acceptance.py
```
