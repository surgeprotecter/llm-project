# 按需求与信息缺口规划旅行

用户用自然语言描述想怎么玩即可。需求模型判断完整旅行、单项查询、目的地筛选或闲聊；完整规划无需用户说“报告”、数据源或工具名称。信息不足先追问，日期用香港当前日期解释省略年份，补充回答与前文合并。

## 同一份城市计划

`reports/route.py` 维护规范地点身份、用户展示名、英文/当地查询名、别名、停留日与住宿日期。景点、酒店和交通共用它。境外地图按当前城市检索，找不到时扩展到国家范围核验具体实体；不会围绕第一个城市过滤整趟行程。

用户考虑新增目的地时，模型比较绕路、时间及其他城市取舍，并在报告中说明；不能无解释删除原城市。明确城市天数作为约束保留与检查。住宿夜晚按实际航班抵达和离境日期计算，途中转机日不虚构酒店。

## 研究与工具决策

- 完整行程：模型先选择城市和进出方式；按城市搜索并读取小红书正文、提取带引用的体验；核验地点；比较每段交通；查询对应住宿。
- 只换酒店：查询指定住宿段，保留景点、交通和原研究。
- 航班增加预算/舒适度：记录在航班偏好，查询机票，复核时刻影响及预算；不会因为提到预算就重新查询酒店。
- 地点不够：补查该城市，而非反复让模型对同一批不足点位重新排程。
- 工具连接成功、HTTP 成功与取得可用结果分别处理；没有核实的经营者、价格和班次不写成事实。

跨城按相邻停留段逐段选择铁路、航班、大巴、渡轮或驾车方案。12306只用于国内、处于售票期的查询；境外地面交通通过网页资料研究，班次参考不冒充实时库存。OSRM仅提供道路驾车估算，不代表有大巴班次。每段保留证据、计价单位、查询时间和未知项，预算对没有报价的部分明确留出金额。

## 每日安排与报告

每日使用同一时间轴表示景点、午晚餐候选、咖啡、商店、活动、交通与休息。活动根据偏好选择。长途转移、跨日航班和全天体验按实际可用时间安排，不机械强迫每天多个景点。用餐候选表示择一，不重复计费。

酒店保存真实图片数组，HTML提供左右切换、键盘与触屏浏览；单图或图片失效有退化处理。餐饮融入每日安排，不再独立堆放一节。HTML和Markdown来自同一结构化快照。

质量检查覆盖城市内容、住宿、转移连续性、时间冲突、日期及预算。未通过的报告显著标为草案并列出缺口；终端优先展示缺口，不能提示完整规划已经完成。

## 上下文与用量

按城市/阶段传递相关正文和短路线摘要；完整来源、酒店图片与工具原始结果保存在本地，不反复发给模型。地点精确匹配与预算算术在本地完成；模糊地点才请模型消歧。静态提取按精确输入缓存，票价和酒店报价不当成静态事实。航班或酒店局部修改复用未变的研究及费用依据，避免重复提取。

真实API usage按调用阶段记录。验收脚本每轮保存实际工具差异、模型输入输出、输入/输出token、报告及未通过原因。调用预算达到上限即停止，不伪装为通过。

## 自己体验

```bash
uv run travel-agent chat --real-only --trace --user-id yuming --trip-id my-natural-test
```

可以从“最近想出去散散心，别太折腾”开始，随后按追问补充。查看完整模型输入输出用 `--trace-full`。CLI支持多行粘贴，长文本也可以先存文件再输入 `/input /绝对路径/需求.txt`。

真实自然对话验收（会发生API与外部工具调用，每组分别执行）：

```bash
uv run python scripts/live_adaptive_acceptance.py domestic_short
uv run python scripts/live_adaptive_acceptance.py international_short
uv run python scripts/live_adaptive_acceptance.py domestic_long
uv run python scripts/live_adaptive_acceptance.py international_long
```

这些提示词不提数据源、MCP或工具名称，覆盖短途与12/14天、国内国外、单城多城、模糊开场及针对性修改。结果位于 `output/adaptive-acceptance/<场景>/<运行时间>/`。每次独立保存，不用后续重跑覆盖旧证据。
